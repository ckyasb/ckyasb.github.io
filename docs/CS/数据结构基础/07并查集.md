# 07 并查集（Union-Find / Disjoint Set）

并查集维护一组**不相交**的集合，支持合并集合与查询所属集合两种操作。因效率极高（均摊近 $O(1)$），常作为图算法（如 Kruskal 最小生成树）的核心工具。

---

## 1. 等价关系与动态等价问题

### 1.1 等价关系

关系 $\sim$ 若满足**自反性**（$a\sim a$）、**对称性**（$a\sim b\Rightarrow b\sim a$）、**传递性**（$a\sim b,\ b\sim c\Rightarrow a\sim c$），则称为等价关系。它将元素划分为若干**等价类**（equivalence classes）。

**等价关系的例子**：相等（$=$）、模 $n$ 同余（$\equiv_n$）、图连通。并查集处理的就是"连通性"这一等价关系的**动态**维护。

### 1.2 动态等价问题

给定 $N$ 个元素，初始每个元素自成一类，随后不断接受两种指令：

- `Union(a, b)` — 合并 $a$ 与 $b$ 所在的等价类。
- `Find(a)` — 返回 $a$ 所属等价类的代表元。

判断 `Find(a) == Find(b)` 即可回答"$a,b$ 是否等价（连通）"。

---

## 2. 基本数据结构

用**树**（森林）表示每个集合：父指针数组 `parent[i]`，根节点为代表元。

| 操作 | 朴素实现 | 复杂度 |
|:---|:---|:---|
| `Find(x)` | 沿父指针走到根 | $O(N)$ 最坏 |
| `Union(x, y)` | 将一棵树根指向另一树根 | $O(1)$ |

朴素实现最坏退化为单链（每次 Union 都把大树接到小树根下），`Find` 代价 $O(N)$。

```c
// 朴素实现
void Initialize( int N ) {
    for ( int i = 0; i < N; i++ )  parent[i] = i;  // 各自成根
}
int Find( int x ) {
    while ( parent[x] != x )  x = parent[x];
    return x;
}
void Union( int x, int y ) {
    parent[ Find(x) ] = Find(y);  // x 的根指向 y 的根
}
```

---

## 3. 智能合并（Smart Union）

### 3.1 按大小合并（Union by Size）

将**较小**树的根指向较大树，保证树高 $\le\log_2 N$。

```c
void Union( int x, int y ) {
    int rx = Find(x), ry = Find(y);
    if ( size[rx] > size[ry] )  parent[ry] = rx, size[rx] += size[ry];
    else                        parent[rx] = ry, size[ry] += size[rx];
}
```

### 3.2 按高度合并（Union by Height）

将**较矮**树的根指向较高树，仅当两树等高时高度增加。

??? note "为何 by Size 保证树高 ≤ log N（课堂证明）"
    **不变量**：任意节点所在子树大小 $\ge 2^{\text{该节点高度}}$（归纳证明）。

    - 基础：叶节点高度 0，子树大小 1 $=2^0$。
    - 归纳：节点 $u$ 高度变为 $h$，仅当它作为**较小树**的根被合并到等高或更高树上。合并后 $u$ 成为子节点，其子树大小至少翻倍（合并了不小于自身的树）。

    故高度 $h$ 的节点子树大小 $\ge 2^h$，而子树大小 $\le N$，故 $h\le\log_2 N$，`Find` $=O(\log N)$。

$$
\boxed{\text{Union by Size / Height 保证 Find} = O(\log N)}
$$

---

## 4. 路径压缩（Path Compression）

在执行 `Find(x)` 时，将沿途所有节点的父指针直接指向根——把路径"拍扁"为高度 1。

??? note "路径压缩的实现"
    ```c
    int Find(int x) {
        if (parent[x] != x)
            parent[x] = Find(parent[x]);  // 递归压缩
        return parent[x];
    }
    ```

    单次 `Find` 代价是路径长度 $h$，但压缩后这条路径上**所有节点**的后续 `Find` 都变成 $O(1)$。

??? note "路径压缩为何有效"
    每次"贵的"`Find`（长路径）都会把路径拍扁，造福后续大量"便宜的"`Find`，整体均摊下来接近常数。与 Union by Size 结合，复杂度降到**反阿克曼函数** $O(\alpha(N))$。

---

## 5. 最坏情况分析

| 策略 | Find 最坏 | 证法 |
|:---|:---|:---|
| 朴素 Union | $O(N)$ | 单链 |
| Union by Size | $O(\log N)$ | 树高至多 $\log N$ |
| Union by Size + Path Compression | $O(\alpha(N))$ | 反阿克曼函数 |

$$
\boxed{\text{均摊复杂度 } O(\alpha(N)),\; \alpha(N) \le 4 \text{ 对 } N \le 10^{540}}
$$

其中 $\alpha(N)$ 是**反阿克曼函数**——增长极慢，$N\le10^{540}$ 时 $\alpha(N)\le4$，实际是常数。这是并查集"近乎 $O(1)$"的根源。

??? note "为何不能严格 $O(1)$"
    理论上并查集的下界是 $\Omega(\alpha(N))$——存在恶意构造的 Union/Find 序列使任何算法都不能快于 $\alpha(N)$。故 $O(\alpha(N))$ 是**最优**的。虽然 $\alpha$ 实际是常数，但理论上它确实非常数。

## 6. 应用

| 应用 | 说明 |
|:---|:---|
| Kruskal 最小生成树 | 按边权排序后，用 Union-Find 检查是否形成环 |
| 网络连通性 | 动态维护网络节点间的连通关系 |
| 图像连通域分析 | 像素合并等价类 |
| 编程语言类型推断 | 类型变量归并 |
| 最近公共祖先（离线 Tarjan） | 利用并查集加速 LCA |

??? note "Kruskal 中的并查集"
    Kruskal 按边权排序后逐条考虑：对边 $(u,v)$，若 `Find(u)==Find(v)`（已连通，加入成环）则跳过，否则 `Union(u,v)` 加入 MST。并查集把"判环"从 $O(V)$ 降到均摊 $O(\alpha(V))$，使 Kruskal 整体 $O(E\log E)$（排序主导）。

## 7. 本章小结

- 等价关系（自反 + 对称 + 传递）划分等价类，并查集动态维护。
- 朴素 Union 退化为链，`Find` $O(N)$。
- Union by Size 小树并大树，树高 $\le\log N$。
- 路径压缩 `Find` 时拍扁路径，与 by Size 结合均摊 $O(\alpha(N))$（反阿克曼，实际常数）。
- 应用：Kruskal 判环、连通性、连通域。

## 8. 典型例题与课堂重点

### 8.1 例题：Union by Size 的树高证明

**题目**：证明按大小合并时树高 $\le\log_2 N$。

??? note "答案要点"
    不变量"任意节点子树大小 $\ge 2^{\text{高度}}$"（归纳：节点高度 $+1$ 当且仅当作为较小树根被合并，子树大小翻倍）。故 $2^h\le N$，$h\le\log_2 N$，`Find` $=O(\log N)$。

### 8.2 例题：路径压缩为何有效

**题目**：路径压缩如何把 `Find` 降到近 $O(1)$？

??? note "答案要点"
    `Find(x)` 时把路径上所有节点父指针指向根——路径被拍扁为高度 1。单次 `Find` 代价是路径长度，但压缩后这条路径上所有节点的后续 `Find` 都 $O(1)$。贵的 `Find` 造福后续便宜操作，均摊 $O(\alpha(N))$。

### 8.3 例题：Kruskal 中的并查集

**题目**：Kruskal 如何用并查集判环？

??? note "答案要点"
    对边 $(u,v)$，`Find(u)==Find(v)` 则已连通加入成环跳过，否则 `Union(u,v)` 加入。并查集把判环从 $O(V)$ 降到均摊 $O(\alpha(V))$，Kruskal 整体 $O(E\log E)$（排序主导）。

### 8.4 课堂重点速记

| 概念 | 关键点 |
|:---|:---|
| 等价关系 | 自反 + 对称 + 传递；划分等价类 |
| 朴素 Union | 退化为链，`Find` $O(N)$ |
| Union by Size | 小树并大树；树高 $\le\log N$ |
| Union by Height | 矮树并高树；等高才增高 |
| 路径压缩 | `Find` 时拍扁路径；与 by Size 结合均摊 $O(\alpha(N))$ |
| $\alpha(N)$ | 反阿克曼；实际常数；理论下界 |
| 应用 | Kruskal 判环、连通性、连通域 |

- 并查集以树结构维护不相交集合，`Union` 和 `Find` 是核心操作
- Union by Size / Union by Height 将树高限制在 $O(\log N)$
- 路径压缩进一步将均摊复杂度降至 $O(\alpha(N))$（实际常数级）
- 广泛应用于图论、动态连通性等领域

## 7. 典型例题与课堂重点

### 7.1 例题：Union by Size 的树高证明

**题目**：证明按大小合并时树高 $\le\log_2 N$。

??? note "答案要点"
    关键不变量：**任意节点所在子树大小 $\ge 2^{\text{该节点高度}}$**（归纳证明）。

    - 基础：叶节点高度 0，子树大小 1 $=2^0$。
    - 归纳：节点 $u$ 高度变为 $h$，仅当它作为**较小树**的根被合并到等高或更高的树上。合并后 $u$ 的高度 +1（成为子），其子树大小至少翻倍（因合并了不小于自身的树）。

    故高度 $h$ 的节点子树大小 $\ge 2^h$，而子树大小 $\le N$，故 $h\le\log_2 N$。

    **推论**：`Find` 沿父指针走，最多 $\log_2 N$ 步，故 `Find` $=O(\log N)$。

### 7.2 例题：路径压缩为何有效

**题目**：路径压缩如何把 `Find` 降到近 $O(1)$？

??? note "答案要点"
    路径压缩在 `Find(x)` 时把从 $x$ 到根路径上**所有节点**的父指针直接指向根——这一路径被"拍扁"为高度 1。

    - 单次 `Find` 的代价是路径长度 $h$，但压缩后这条路径上**所有节点**的后续 `Find` 都变成 $O(1)$。
    - 摊还分析（与 Union by Size 结合）给出**均摊** $O(\alpha(N))$，其中 $\alpha$ 是反阿克曼函数——增长极慢，$N\le 10^{540}$ 时 $\alpha(N)\le 4$，实际是常数。

    直觉：每次"贵的" `Find`（长路径）都会把路径拍扁，造福后续大量"便宜的" `Find`，整体均摊下来接近常数。

### 7.3 例题：Kruskal 中的并查集

**题目**：Kruskal 算法如何用并查集判环？

??? note "答案要点"
    Kruskal 按边权排序后逐条考虑：对边 $(u,v)$，若 `Find(u) == Find(v)`（$u,v$ 已在同一连通分量，即同一集合），则加入此边会成环，**跳过**；否则 `Union(u,v)` 加入 MST。

    并查集把"判环"从 $O(V)$ 降到均摊 $O(\alpha(V))$，使 Kruskal 整体 $O(E\log E)$（排序主导）。
