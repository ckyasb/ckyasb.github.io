# 06 散列（Hashing）

散列是一种以 $O(1)$ **期望时间**实现插入、删除和查找的技术。核心是通过**散列函数**（hash function）将键映射到数组下标。

---

## 1. 散列表 ADT

散列表（hash table）用一个固定大小的数组 `T[0..M-1]` 存储元素。设计目标：
- **散列函数**：将键均匀分布到 $[0, M-1]$
- **冲突解决**：处理两个键映射到同一位置的情况

---

## 2. 散列函数

### 2.1 整数键

??? note "自测"
    **Q**: 取模哈希中，模数 $M$ 为何通常选素数？

    ??? note "答案"
        若 $M$ 含小因子（如 $2^k$），而键的分布也含该因子结构，哈希值会聚集到少数槽位；素数 $M$ 使 $x\bmod M$ 对各种键分布都接近均匀。

- **直接取模**：$\text{hash}(x) = x \bmod M$
  - $M$ 通常选**素数**以减少聚集
- **平方取中**：$x^2$ 的中间若干位

### 2.2 字符串键

??? note "自测"
    **Q**: 字符串哈希为何用质数基底（如 37）？这叫什么方法？

    ??? note "答案"
        质数基底使不同字符串的哈希值冲突概率低，避免合数基底的周期性退化；这叫 **Horner 法则**的多项式哈希。

$$
\text{hash}(s) = \sum_{i=0}^{k-1} s[i] \cdot 37^{i} \pmod M
$$

使用质数基底（如 37）减少冲突，称为 **Horner 法则**的多项式哈希。

---

## 3. 冲突解决

### 3.1 分离链接法（Separate Chaining）

??? note "自测"
    **Q**: 分离链接法中，负载因子 $\lambda$ 偏大时查找性能为何退化？

    ??? note "答案"
        $\lambda = N/M$ 等于链表平均长度，查找/删除与链表长度成正比。$\lambda$ 偏大则链表变长，查找从 $O(1)$ 线性退化。

每个槽位维护一个链表。插入 $O(1)$，查找 / 删除与链表长度成正比。

| 负载因子 $\lambda = N/M$ | 查找期望时间 |
|:---|:---|
| $\lambda \approx 1$ | $O(1)$ |
| $\lambda$ 偏大 | 线性退化 |

### 3.2 开放定址法（Open Addressing）

??? note "自测"
    **Q**: 开放定址法为何要求负载因子 $\lambda < 1$？平方探测更严格的条件是什么？

    ??? note "答案"
        $\lambda \ge 1$ 时表无空位，找不到插入位置。平方探测要求 $M$ 为素数且 $\lambda \le 1/2$ 才能保证一定能找到空位。

所有元素直接存储在表中，冲突时寻找下一个可用位置。

#### 线性探测（Linear Probing）

$$
\text{hash}'(x, i) = (\text{hash}(x) + i) \bmod M
$$

- 优点：实现简单，缓存友好
- 缺点：**一次聚集**（primary clustering），易形成长探针序列

#### 平方探测（Quadratic Probing）

$$
\text{hash}'(x, i) = (\text{hash}(x) + i^2) \bmod M
$$

- 消除一次聚集，但仍有**二次聚集**
- 若 $M$ 为素数且表负载 $\le 1/2$，一定能找到空位

#### 双散列（Double Hashing）

$$
\text{hash}'(x, i) = (\text{hash}_1(x) + i \cdot \text{hash}_2(x)) \bmod M
$$

其中 $\text{hash}_2(x)$ 给出第二个步长，基本消除聚集。

| 方法 | 探针序列 | 聚集问题 |
|:---|:---|:---|
| 线性探测 | $1, 2, 3, \ldots$ | 一次聚集严重 |
| 平方探测 | $1, 4, 9, \ldots$ | 二次聚集较轻 |
| 双散列 | 依赖 $\text{hash}_2$ | 接近无聚集 |

## 4. 再散列（Rehashing）

当负载因子超过阈值时，建一个**更大**的散列表（通常 $2\times$），将所有元素重新插入。

$$
\boxed{\text{再散列代价} = O(N)}
$$

虽然单次代价大，但**摊还分析**表明平均仍为 $O(1)$。

??? note "再散列的时机与摊还分析"
    触发再散列的负载因子阈值：

    - 分离链接：$\lambda$ 可较大（如 1），但链表变长查找变慢，通常 $\lambda>1$ 时再散列。
    - 开放定址：必须 $\lambda<1$（否则找不到空位）；平方探测要求 $\lambda\le0.5$ 保证成功，故阈值更低。

    **摊还分析**：设阈值 $\lambda_0$，表从 $M$ 扩到 $2M$ 期间可插入约 $\lambda_0 M$ 个元素（每个 $O(1)$），再散列 $O(M)$ 摊到 $\lambda_0 M$ 次上得 $O(1)$。与动态数组扩容同构。

---

## 5. 可扩展散列（Extendible Hashing）

用于**外存**的散列结构，通过**目录**（directory）和**桶**（bucket）的层次化设计：

- 目录按**前 $d$ 位**（$d$ 为全局深度）划分桶，桶满时分裂。
- 每次分裂只影响一个桶及其关联目录项，**局部**性高。
- 桶有局部深度 $d'$，仅当 $d'=d$ 时分裂才需扩大目录。

适用于数据量动态增长且需最小化 I/O 的场景（数据库索引）。

## 6. Robin Hood 哈希（课堂补充专题）

Robin Hood 哈希是线性探测的改进变体（Pedro Celis, 1986），核心思想"**劫富济贫**"——减少探测距离的方差。

### 6.1 探测距离

??? note "自测"
    **Q**: Robin Hood 哈希中，键 $x$ 的探测距离 $d(x)$ 如何定义？$d$ 越大代表什么？

    ??? note "答案"
        $d(x) = (g(x) - h(x)) \bmod \text{TableSize}$，其中 $g(x)$ 是实际存放位置，$h(x)$ 是初始哈希位置。$d$ 越大表示键"离家越远"（越"穷"）。

$$
d(x) = (g(x) - h(x)) \bmod \text{TableSize}
$$

$g(x)$ 是 $x$ **实际存放位置**，$h(x)$ 是初始哈希位置。$d$ 越大键"离家越远"（越"穷"）。

### 6.2 插入算法

??? note "自测"
    **Q**: Robin Hood 插入时，什么条件下会触发"交换"操作？

    ??? note "答案"
        当当前键的探测距离 `CurrentDisp` > 占位键的 `Disp`（当前键更"穷"）时，交换两者，让更"穷"的键先安顿。

```c
bool RobinHood_Insert( ElementType Key, HashTable H ) {
    Position Pos = Hv = Hash( Key, H->TableSize );
    int CurrentDisp = 0;
    ElementType currentKey = Key;
    while ( true ) {
        if ( H->TheCells[ Pos ].Info != Legitimate ) {  // 空位或已删
            H->TheCells[ Pos ].Info = Legitimate;
            H->TheCells[ Pos ].Element = currentKey;
            H->TheCells[ Pos ].Disp = CurrentDisp;
            return true;
        }
        if ( CurrentDisp > H->TheCells[ Pos ].Disp ) {  // 当前键更"穷"
            swap( &currentKey, &H->TheCells[ Pos ].Element );  // 抢位置
            swap( &CurrentDisp, &H->TheCells[ Pos ].Disp );
        }
        Pos = (Pos + 1) % H->TableSize;
        if ( Pos == Hv )  return false;                  // 表满
        CurrentDisp++;
    }
}
```

??? note "劫富济贫的逻辑"
    插入 $x$ 沿探针前进，若某位置已被 $y$ 占据且 $x$ 当前的探测距离 `CurrentDisp` > $y$ 的 `Disp`（$x$ 比 $y$ 更"穷"），则**交换**：把 $x$ 放入该位置，$y$ 被踢出继续前进。总让更"穷"的键先安顿，使探测距离分布均匀。

### 6.3 性能与查找

??? note "自测"
    **Q**: Robin Hood 哈希为何能把最坏查找从 $O(N)$ 降到 $O(\log N)$？

    ??? note "答案"
        探针序列上各位置 `Disp` **单调不减**，查找时一旦遇到 `Disp > CurrentDisp` 即可提前终止，无需走完整条链。

| 特性 | 说明 |
|:---|:---|
| 期望探针数 | 与线性探测同渐近，常数略低 |
| **最坏情况** | 从 $O(N)$ 改善到 $O(\log N)$（关键优势） |
| 高负载容忍 | 负载因子高时仍可预测性能 |
| 缺点 | 插入较慢、删除复杂、需额外存储 `Disp` |

??? note "查找的提前终止（atan 思想）"
    Robin Hood 保证沿探针序列前进时各位置 `Disp` **单调不减**。查找 $x$ 时沿探针走，一旦 `Disp > CurrentDisp`（当前查找距离）即可**提前终止**——$x$ 不在表中。这一单调性把最坏查找从 $O(N)$ 降到 $O(\log N)$。

## 7. 本章小结

- 散列函数将键映射到数组下标，目标为均匀分布（模数取素数、字符串用多项式）。
- 冲突解决分**分离链接**（链表）和**开放定址**（探针）两类。
- 探测方法的选择影响聚集行为：线性一次聚集、平方二次聚集、双散列接近无聚集。
- 再散列保持负载因子在安全范围，摊还 $O(1)$。
- 可扩展散列通过目录-桶结构适配外存。
- Robin Hood 哈希"劫富济贫"，把最坏查找从 $O(N)$ 降到 $O(\log N)$。

## 6. Robin Hood 哈希（课堂补充专题）

Robin Hood 哈希是线性探测的一种改进变体（Pedro Celis, 1986），核心思想是"**劫富济贫**"——减少探测距离的方差。

### 6.1 动机

??? note "自测"
    **Q**: Robin Hood 哈希"劫富济贫"的目标是什么？改善的是期望还是最坏？

    ??? note "答案"
        通过让"穷键"抢"富键"位置，使探测距离分布均匀、降低方差；主要改善**最坏情况**（从 $O(N)$ 降到 $O(\log N)$）。

线性探测虽然缓存友好，但当负载因子高时探针序列变长且**方差大**（有的键探测 1 次，有的探测几十次）。Robin Hood 通过让"探测距离远的穷键"抢"探测距离近的富键"的位置，使所有键的探测距离尽量接近，降低**最坏情况**。

### 6.2 探测距离

??? note "自测"
    **Q**: 探测距离 $d(x)$ 的定义中，$g(x)$ 和 $h(x)$ 分别指什么？

    ??? note "答案"
        $h(x)$ 是键 $x$ 的初始哈希位置，$g(x)$ 是 $x$ 实际存放位置；$d(x) = (g(x) - h(x)) \bmod \text{TableSize}$。

定义键 $x$ 的探测距离：

$$
d(x) = (g(x) - h(x)) \bmod \text{TableSize}
$$

其中 $g(x)$ 是 $x$ **实际存放位置**，$h(x)$ 是 $x$ 的初始哈希位置。$d$ 越大表示这个键"离家越远"（越"穷"）。

### 6.3 插入算法

??? note "自测"
    **Q**: Robin Hood 插入遇到空位直接放入；若被占，何时交换？交换后谁继续前进？

    ??? note "答案"
        当 `CurrentDisp > 占位键.Disp` 时交换：当前键放入该位置，被踢出的占位键带着其 `Disp` 继续沿探针前进。

```c
bool RobinHood_Insert( ElementType Key, HashTable H ) {
    Position Pos = Hv = Hash( Key, H->TableSize );
    int CurrentDisp = 0;
    ElementType currentKey = Key;
    while ( true ) {
        if ( H->TheCells[ Pos ].Info != Legitimate ) {  // 空位或已删
            H->TheCells[ Pos ].Info = Legitimate;
            H->TheCells[ Pos ].Element = currentKey;
            H->TheCells[ Pos ].Disp = CurrentDisp;       // 记录探测距离
            return true;
        }
        if ( CurrentDisp > H->TheCells[ Pos ].Disp ) {  // 当前键比占位键"更穷"
            swap( &currentKey, &H->TheCells[ Pos ].Element );  // 抢位置
            swap( &CurrentDisp, &H->TheCells[ Pos ].Disp );
        }
        Pos = (Pos + 1) % H->TableSize;
        if ( Pos == Hv )  return false;                  // 表满
        CurrentDisp++;
    }
}
```

??? note "劫富济贫的逻辑"
    插入 $x$ 沿探针序列前进，若某位置已被键 $y$ 占据，且 $x$ 当前的探测距离 `CurrentDisp` > $y$ 的 `Disp`（即 $x$ 比 $y$ 更"穷"、离家更远），则**交换**：把 $x$ 放入该位置，$y$ 被踢出继续前进。这样总让更"穷"的键先安顿，使探测距离分布更均匀。

### 6.4 性能特点

??? note "自测"
    **Q**: Robin Hood 哈希查找时为何能提前终止？这一性质把最坏查找降到多少？

    ??? note "答案"
        探针序列上 `Disp` 单调不减，查找时一旦 `Disp > CurrentDisp` 即可判定键不在表中，提前终止；最坏查找降到 $O(\log N)$。

| 特性 | 说明 |
|:---|:---|
| 期望探针数 | 与线性探测同渐近增长，常数略低 |
| **最坏情况** | 从 $O(N)$ 改善到 $O(\log N)$（关键优势） |
| 高负载容忍 | 负载因子高时仍可预测性能 |
| 缺点 | 插入较慢、删除复杂、需额外存储 `Disp` |

??? note "如何查找（用 atan 思想）"
    Robin Hood 哈希保证：沿探针序列前进时，各位置的 `Disp` **单调不减**。因此查找 $x$ 时沿探针走，一旦遇到 `Disp > CurrentDisp`（当前查找的探测距离）即可**提前终止**——$x$ 不在表中。这一单调性把最坏查找从 $O(N)$ 降到 $O(\log N)$。

## 7. 典型例题与课堂重点

### 7.1 例题：散列函数设计

**题目**：为何取模哈希的模数 $M$ 要选素数？字符串哈希为何用质数基底？

??? note "答案要点"
    - **模数选素数**：若 $M$ 有小因子（如 $M=2^k$），而键的分布也含该因子结构（如偶数键多），则哈希值会聚集到少数槽位。素数 $M$ 使 $x\bmod M$ 对各种键分布都接近均匀。
    - **字符串质数基底**：多项式哈希 $\sum s[i]\cdot b^i$ 用质数 $b$（如 37）使不同字符串的哈希值冲突概率低；若用合数基底，会产生周期性退化。

### 7.2 例题：开放定址法的聚集

**题目**：线性探测为何产生一次聚集？平方探测为何产生二次聚集？双散列如何缓解？

??? note "答案要点"
    - **一次聚集**（线性）：冲突键都走 $+1,+2,\ldots$，形成连续占用的"块"，新键落进块内就要走到底，块越长越易吸引新冲突——正反馈使块越长。
    - **二次聚集**（平方）：平方探测下，**哈希值相同**的键走相同的 $+1,+4,+9,\ldots$ 序列，互相碰撞。它消除了"哈希值不同但探针路径交叠"的一次聚集，但未消除"哈希值相同"导致的聚集。
    - **双散列**：用 `hash2(x)` 给每个键**不同的步长**，使哈希值相同的键也走不同路径，接近无聚集。

### 7.3 例题：再散列的摊还分析

**题目**：再散列单次 $O(N)$，为何平均仍 $O(1)$？

??? note "答案要点"
    摊还分析（聚合法）：设负载因子阈值 $\lambda_0$，表从 $M$ 扩到 $2M$ 之间可插入约 $\lambda_0 M$ 个元素（每个 $O(1)$），摊到这 $\lambda_0 M$ 次操作上，再散列的 $O(M)$ 摊还 $O(M)/\lambda_0 M = O(1)$。故插入的**摊还**复杂度仍 $O(1)$。

    这与动态数组的倍增扩容是同一套摊还分析。

### 7.4 课堂重点速记

| 概念 | 关键点 |
|:---|:---|
| 散列函数 | 模数取素数；字符串用多项式（质数基底） |
| 分离链接 | 链表存冲突；负载 $\lambda=N/M$，查找 $O(1+\lambda)$ |
| 线性探测 | 一次聚集；缓存友好 |
| 平方探测 | 二次聚集；$\lambda\le 0.5$ 且 $M$ 素数保证找到空位 |
| 双散列 | 用 `hash2` 给不同步长，接近无聚集 |
| 再散列 | $\lambda$ 超阈值时扩表 2 倍；摊还 $O(1)$ |
| 可扩展散列 | 外存；目录 + 桶；桶满分裂 |
| Robin Hood | 劫富济贫；最坏 $O(\log N)$；`Disp` 单调不减 |
