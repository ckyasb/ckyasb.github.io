# 04 优先队列与堆（Priority Queues & Heaps）

优先队列是支持**高效取出最大（或最小）元素**的数据结构。堆是其最经典的实现，也是堆排序、Dijkstra 最短路、Huffman 编码等算法的核心组件。

---

## 1. 优先队列的需求

| 操作 | 期望复杂度 |
|:---|:---|
| `Insert(x)` | $O(\log N)$ |
| `DeleteMin()` / `DeleteMax()` | $O(\log N)$ |
| `FindMin()` / `FindMax()` | $O(1)$ |

朴素实现对比：

| 实现 | Insert | DeleteMin |
|:---|:---|:---|
| 无序数组/链表 | $O(1)$ | $O(N)$（需扫描找最值） |
| 有序数组/链表 | $O(N)$（需插入到位） | $O(1)$ |
| **二叉堆** | $O(\log N)$ | $O(\log N)$ |
| 二项堆/斐波那契堆 | $O(1)$ 均摊 | $O(\log N)$ |

二叉堆在实现复杂度和效率间取得最佳平衡，是本课重点。

---

## 2. 二叉堆（Binary Heap）

### 2.1 两个性质

1. **结构性**（structure）：堆是一棵**完全二叉树**——除最后一层外全满，最后一层从左到右连续。这保证可用数组紧凑存储。
2. **堆序性**（heap order）：
   - **最小堆**（min-heap）：任一节点的值 $\le$ 其子节点值（根最小）。
   - **最大堆**（max-heap）：任一节点的值 $\ge$ 其子节点值（根最大）。

### 2.2 数组存储

完全二叉树用数组存储（下标从 1 开始最方便）：

- 节点 $i$ 的父节点：$\lfloor i/2\rfloor$
- 节点 $i$ 的左子：$2i$
- 节点 $i$ 的右子：$2i+1$

```c
struct HeapStruct {
    int Capacity;
    int Size;
    ElementType *Elements;  // Elements[0] 留作哨兵
};
```

??? note "哨兵（Sentinel）技巧"
    `Elements[0]` 存一个比所有元素都小（最小堆）的值，作为哨兵。这样 `PercolateUp` 比较到根时无需额外判断越界——`while (X < A[i/2])` 在 `i=1` 时自动停止（因 `A[0]` 最小）。这是工程上常见的边界简化。

---

## 3. 堆的核心操作

### 3.1 插入：Percolate Up（上滤）

把新元素放在数组末尾（保持结构性），然后向上与父节点比较，若违反堆序则交换，直到满足堆序。

```c
void Insert( ElementType X, PriorityQueue H ) {
    int i;
    for ( i = ++H->Size; H->Elements[i/2] > X; i /= 2 )
        H->Elements[i] = H->Elements[i/2];   // 父节点下移
    H->Elements[i] = X;                        // 找到位置
}
```

**复杂度**：最坏 $O(\log N)$（沿树高一路上滤）。

### 3.2 删除最小：Percolate Down（下滤）

最小堆的 `DeleteMin` 取出根（最小值），把**最后一个元素**搬到根位置，然后向下与较小的子节点比较交换，直到满足堆序。

```c
ElementType DeleteMin( PriorityQueue H ) {
    int i, Child;
    ElementType MinElement = H->Elements[1];
    ElementType LastElement = H->Elements[H->Size--];
    for ( i = 1; i*2 <= H->Size; i = Child ) {
        Child = i*2;
        if ( Child != H->Size && H->Elements[Child+1] < H->Elements[Child] )
            Child++;                            // 选较小的子
        if ( LastElement > H->Elements[Child] )
            H->Elements[i] = H->Elements[Child]; // 子上移
        else  break;
    }
    H->Elements[i] = LastElement;
    return MinElement;
}
```

**复杂度**：最坏 $O(\log N)$。

??? note "为何选较小的子节点比较"
    下滤时要把根值与两个子节点中**较小**的那个比较——若要交换，必须把较小的子提上来（保持父 $\le$ 子）。若选较大的子交换，会破坏堆序。

### 3.3 其他操作

| 操作 | 实现 | 复杂度 |
|:---|:---|:---|
| `FindMin` | 直接读根 `Elements[1]` | $O(1)$ |
| `DecreaseKey(p, Δ)` | 减小某位置值，对该位置 `PercolateUp` | $O(\log N)$ |
| `IncreaseKey(p, Δ)` | 增大某位置值，对该位置 `PercolateDown` | $O(\log N)$ |
| `Delete(p)` | `DecreaseKey(p, +∞)` 后 `DeleteMin` | $O(\log N)$ |
| `BuildHeap` | 见 §4 | $O(N)$ |

## 4. BuildHeap：$O(N)$ 建堆

给定 $N$ 个元素的数组，建立最小堆。有两种方法：

- **逐个 Insert**：$N$ 次 `PercolateUp`，最坏 $O(N\log N)$。
- **自底向下 `PercolateDown`**：从最后一个非叶子节点（下标 $\lfloor N/2\rfloor$）开始，**从右到左、从下到上**对每个节点做一次 `PercolateDown`。**整体 $O(N)$**——比逐个插入更优！

```c
void BuildHeap( PriorityQueue H ) {
    for ( int i = H->Size/2; i > 0; i-- )
        PercolateDown( i, H );
}
```

??? note "为何 BuildHeap 是 O(N) 而非 O(N log N)"
    关键洞察：堆中**大多数节点在底层**，而底层节点 `PercolateDown` 几乎不动（最多下移 0 层）；只有靠近根的少数节点下移多。精确求和：

    $$
    T(N) = \sum_{h=0}^{\log N}(\text{高度为 }h\text{ 的节点数})\times h \le \sum_{h=0}^{\log N}\left\lceil\frac{N}{2^{h+1}}\right\rceil h = O(N)
    $$

    指数衰减的权重大头集中在底层，总和收敛于 $O(N)$。这是堆最重要的复杂度结论之一。

??? note "课堂例题：BuildHeap 过程"
    对数组 `[150, 80, 40, 30, 10, 70, 110, 100, 20, 90, 60, 50, 120, 140, 130]`（共 15 元素）建最小堆：

    - 从 `i = 7`（节点 110）开始 `PercolateDown`，逐个向上处理到 `i=1`。
    - 每次处理时把当前节点下滤到合适位置。
    - 由于底层多、变动少，整体仅 $O(N)$ 次比较。

    最终得到合法最小堆，根为最小值 10。

## 5. 堆排序（HeapSort）

堆排序利用最大堆实现原地 $O(N\log N)$ 排序：

1. **建堆**：对数组 `BuildHeap`（建最大堆），$O(N)$。
2. **反复取最大**：每次把根（最大值）与末尾交换，缩小堆规模 1，对新根 `PercolateDown`。重复 $N-1$ 次。

```c
void Heapsort( ElementType A[], int N ) {
    BuildHeap( A, N );              // O(N)
    for ( int i = N-1; i > 0; i-- ) {
        Swap( &A[0], &A[i] );       // 最大值归位
        PercolateDown( A, 0, i );   // 对剩余 i 个元素下滤
    }
}
```

| 性质 | 值 |
|:---|:---|
| 时间复杂度 | $O(N\log N)$（最坏、平均、最佳都是） |
| 空间复杂度 | $O(1)$（原地） |
| 稳定性 | **不稳定** |

??? note "堆排序为何不稳定"
    堆排序中相等元素的相对顺序可能被 `PercolateDown` 的交换打乱——例如两个相等元素，一个在根附近、一个在底层，下滤交换后相对顺序改变。这是堆排序相对归并排序的主要缺点。

??? note "堆排序 vs 快排 vs 归并"
    | 算法 | 平均 | 最坏 | 空间 | 稳定 | 缓存友好 |
    |:---|:---|:---|:---|:---|:---|
    | 快排 | $O(N\log N)$ | $O(N^2)$ | $O(\log N)$ | 否 | 是 |
    | 堆排 | $O(N\log N)$ | $O(N\log N)$ | $O(1)$ | 否 | 否（跳跃访问） |
    | 归并 | $O(N\log N)$ | $O(N\log N)$ | $O(N)$ | 是 | 是 |

    堆排的最大优势是**最坏 $O(N\log N)$ + 原地**，但跳跃式数组访问使缓存命中率低，实际常数比快排大。归并适合外部排序与链表。

## 6. 优先队列的其他实现

### 6.1 d-堆（d-Heap）

每个节点最多 $d$ 个子节点。树高 $\log_d N$（比二叉堆浅），但 `DeleteMin` 要比较 $d$ 个子节点选最小，代价 $O(d)$。

- 适合**插入多、删除少**的场景（插入 $O(\log_d N)$ 更快）。
- 不适合 `DecreaseKey` 频繁的场景。

### 6.2 左式堆、斜堆、二项堆、斐波那契堆

| 结构 | 合并 `Merge` 复杂度 | 特点 |
|:---|:---|:---|
| 二叉堆 | $O(N)$ | 需重建 |
| 左式堆 | $O(\log N)$ | 用"零路径长"维持倾斜 |
| 斜堆 | $O(\log N)$ 均摊 | 左式堆的自适应版 |
| 二项堆 | $O(\log N)$ | 由多棵不同高度二项树组成 |
| 斐波那契堆 | $O(1)$ 均摊 | `DecreaseKey` $O(1)$ 均摊，Dijkstra 理论最优 |

??? note "斐波那契堆为何理论最优但实践少用"
    斐波那契堆的 `DecreaseKey` 和 `Insert` 都是 $O(1)$ 均摊，使 Dijkstra 降到 $O(E+V\log V)$。但实现极其复杂、常数大，实践中二项堆/配对堆通常更优。它更多是理论分析的标杆。

## 7. 应用

| 应用 | 用法 |
|:---|:---|
| **堆排序** | 见 §5 |
| **选择问题（Top-K）** | 维护大小为 $K$ 的堆，扫描一遍 $O(N\log K)$ |
| **Dijkstra 最短路** | 用最小堆取当前最近未访问点 |
| **Prim 最小生成树** | 用最小堆取最小权横切边 |
| **Huffman 编码** | 每次取两个最小频率节点合并 |
| **合并 K 个有序链表** | 用大小为 $K$ 的堆 |
| **中位数维护** | 一个最大堆（前半）+ 一个最小堆（后半） |

??? note "课堂例题：Top-K 问题"
    从 $N$ 个数中找最大的 $K$ 个（$K\ll N$）：

    - **方法一**：全部排序后取前 $K$，$O(N\log N)$。
    - **方法二**：维护大小为 $K$ 的**最小堆**，扫描每个数：若比堆顶大则替换堆顶并 `PercolateDown`。$O(N\log K)$。

    方法二在大数据流（内存放不下全部）场景下尤其重要——只需 $O(K)$ 内存。

??? note "课堂例题：数据流中位数"
    维护两个堆：

    - **最大堆 `low`** 存较小的一半（堆顶是这半的最大值）。
    - **最小堆 `high`** 存较大的一半（堆顶是这半的最小值）。
    - 保持两堆规模差 $\le 1$。

    插入新数时：若比 `low` 堆顶小则入 `low`，否则入 `high`；再平衡两堆规模。查询中位数：若两堆等大取两堆顶平均，否则取大堆顶。每次操作 $O(\log N)$。

---

## 本章小结

- 优先队列支持高效取最值；二叉堆用**完全二叉树 + 堆序性**实现，数组存储。
- 核心操作 `PercolateUp`/`PercolateDown` 均 $O(\log N)$；`BuildHeap` 利用底层节点多达到 $O(N)$。
- 堆排序是原地、最坏 $O(N\log N)$ 但不稳定的排序。
- 优先队列广泛用于图算法（Dijkstra/Prim）、Huffman 编码、Top-K、流式中位数等。
